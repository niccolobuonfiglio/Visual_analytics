Neighbourhood search  simulated annealing

,
Why this is needed. The F1-score as a function of the neighbourhood size k is neither concave nor convex: enlarging k steadily raises recall but lowers precision in a bumpy way, so the combined score has several local peaks. A plain scan is wasteful and gradient methods get stuck, so the toolkit anneals, it accepts occasional worsening moves early on to escape local optima, then cools to refine. Crucially, no projection is recomputed during the search; only the similarity graph is rebuilt, which is what makes it cheap.

Adjusted-distance MDS

Method
What it does. Ordinary MDS uses the plain Euclidean distance, so noisy or dominant features drive the layout. An adjusted distance reweights the space so the projection preserves neighbourhoods better. Two label-free methods:
  • Locality weighting (default), weights each feature by its Laplacian Score: a feature counts more if it varies little between nearby points (it respects the local manifold), and noisy features that vary randomly are down-weighted. You can hand-tune each feature's weight below.
  • Mahalanobis, whitens by the inverse covariance d = √((a−b)ᵀΣ⁻¹(a−b)). Standard, but whitening amplifies low-variance directions, which are often noise, so on these datasets it tends to make F1 worse, which the panel below shows honestly.
Only the MDS panel changes; PCA and the trust scores stay on the true geometry. Whether it helps is measured below (neighbourhood-F1 and FP/FN rates, plain vs adjusted).
